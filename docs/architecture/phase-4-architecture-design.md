# Phase 4 architecture design — search, knowledge, and optional AI

## Status

Phase 4 has started on `feat/phase-4-search-knowledge-ai`, based on `master` at `005888a`. Phase 3 remains open for the separately deferred Meta API-key and live-provider verification. Starting Phase 4 does not pass or close Phase 3.

## Product contract

- Library search and knowledge views must work with AI providers and local ML services disabled.
- Keep all retrieval owner-scoped in the API/database layer. Filters, pagination, and ordering must be deterministic and reflected in URL state.
- Treat OCR, transcripts, summaries, visual descriptions, and embeddings as derived artifacts with provider/model, source item, and generation provenance. Never overwrite user-authored notes.
- Any grounded answer must cite item IDs that were actually retrieved for the signed-in owner; do not present generated claims as source facts.
- AI enrichment remains optional, bounded, rate-limited, and failure-tolerant. Provider credentials stay server-side. Provider absence or failure must not block capture, library browsing, or keyword search.
- No provider key is required for this initial deterministic retrieval slice. Real provider authorization and media behavior remain a later Phase 3 verification item.

## Source-backed scope

The Phase 4 capability rows are library search and retrieval, OCR/ASR/visual interpretation, item summaries/citations, Smart Collection rule evaluation, Library Checkup diagnostics, and the Knowledge Graph. Source references include `apps/orchestration/src/services/aiSearch.js`, `graph.js`, `libraryCare.js`, `smartCollections.js`, the UI `LibraryTab.jsx`, `GraphTab.jsx`, `LibraryCheckupTab.jsx`, and `SmartCollectionsView.jsx` in the read-only IScraper checkout. Rembr-specific APIs and schemas are required; source code is evidence, not a copy target.

## Implementation sequence

1. Improve deterministic library retrieval first: search effective title, description, URL, extracted text, and existing analysis artifacts; provide relevance ordering with stable owner-bound pagination and keep filters usable.
2. Add search feedback and a small, fixture-grounded retrieval evaluation. Record measurements and limitations before introducing semantic reranking.
3. Reconcile and implement Knowledge Graph, Checkup, and Smart Collection rule capabilities against the source acceptance matrix, with accessible non-visual alternatives and deterministic behavior.
4. Add grounded summaries/chat and OCR/ASR/visual enrichment behind provider/local-runtime adapters. Validate outputs, cap input/output/time/usage, preserve source provenance and citations, and support missing-key/provider-failure states.
5. Complete owner-isolation, deletion/artifact lifecycle, provider-off/failure, keyboard/responsive, and local regression evidence before deciding the Phase 4 gate.

## First implementation slice

Implemented locally on this branch: deterministically rank library search results by matches across effective title, description, URL, extracted text, note bodies, and existing AI analysis. Search remains tenant-scoped and provider-independent; relevance pagination carries score/date ordering in its owner-bound cursor. No production database mutation or provider call was part of this slice. Typecheck, lint, production build, and `git diff --check` passed; automated tests and browser review have not been run.

## Additional provider-free slices

- Knowledge Graph API and screen: derive bounded item/concept relationships from the signed-in user's domains, tags, collections, opt-in analysis topics, and typed brands/tools/people/repositories when present. The SVG is a compact sample; the grouped concept/item list is the complete accessible interaction surface. No new persistence or provider call is required.
- Knowledge Graph screen: users can download the currently loaded owner-scoped graph as versioned JSON, with export time, node/link/group data, counts, and an explicit completeness/truncation flag. A separate owner-scoped Obsidian ZIP export now includes every saved item, concept notes, wikilinks, user notes, available summaries, and `graph.json`; the full export is integration-tested. Browser review and production-size runtime evidence remain open.
- Library Checkup API and screen: report owner-scoped processing states, unorganized saves, older saves, and stable daily/weekly rediscovery picks. Explicit user-scheduled reminders support tomorrow/week/month presets and pending/due/done/dismissed handling. Reminders are only created or changed on user action. Migration `20261029160000_rembr_library_reminders.sql` is local and still needs deployment evidence.
- Link health: a user-triggered Checkup action probes up to 10 owner-scoped page links per request, revalidates public destinations at each redirect, uses HEAD with a bounded GET fallback, and records `ok`, `broken` (404/410), or `unknown` evidence with a seven-day cooldown. Migration `20261029170000_rembr_link_health_checks.sql` is local. The database's unique `(owner_id,canonical_url)` constraint prevents duplicate saves by design; reference duplicate cleanup has no corresponding Rembr data case.
- Smart Collections API, persistence, and screens: deterministically derive rule/topic/capture/folder/platform groups from up to 2,000 recent owner saves and existing analysis, including summary, visual description, OCR, transcript, tags, keywords, and typed brands/tools/people/repositories. Typed labels are bounded and stored with the analysis generation; people names may come only from explicit post text or OCR, never face identification. Media-analysis consent v2 is required, so earlier opt-ins do not authorize entity extraction. The UI exposes inline rename, library search for adding saves, undo for manual additions, and a removed-items list for restoring automatic matches. Override-backed groups remain available if current automatic matches fall below the two-item suggestion threshold. Search and membership reads remain owner-scoped; no provider is called by Smart Collection rule evaluation. Rules run on refresh and group open, with text inputs bounded to 2,000 characters per item. Migrations `20261029150000_rembr_smart_collections.sql` and `20261029210000_rembr_analysis_entity_labels.sql` are local and still need deployment/database migration evidence.
- Search feedback: persist a bounded owner-scoped result event for non-empty searches and accept helpfulness ratings only for items in that event's result set. Store a query hash and length rather than raw query text. Search continues if feedback logging is unavailable. The six-item fixture in `docs/quality/phase-4-search-retrieval-evaluation.md` now runs through the API and calculates synthetic MRR/nDCG; it remains too small to represent real retrieval quality.
- Grounded library chat: `/api/knowledge/answer` retrieves up to eight owner-scoped library matches and accepts bounded recent conversation context for follow-up questions. The UI keeps the conversation in page memory; the API considers only recent user questions when expanding retrieval and treats all conversation as untrusted context, never evidence. By default it returns saved evidence excerpts without a provider call. A separate, off-by-default disclosure (v5) covers recent conversation, matching saved text and existing media-analysis snippets (summary, visual description, OCR, transcript, keywords, topics, and matching typed brand/tool/person/repository labels), and explicitly requested saved-item source text; older consent versions are not accepted for provider calls. Generated claims are kept only when each cites an ID in that turn's retrieved set. Inputs/output are bounded and rate-limited; preflight and settled token usage share the existing monthly AI cap with import analysis. Unknown or over-budget outcomes remain held in an owner-scoped ledger. Missing providers, malformed output, or errors fall back to the excerpt preview. Conversation is not persisted across reloads. Consent migration `20261029220000_rembr_grounded_search_entity_disclosure.sql`, usage, and summary migrations are local and still need hosted migration/runtime evidence. No Meta API key or live provider behavior was verified.
- User-requested saved-item summaries: `POST /api/knowledge/items/:itemId/summary` sends at most 6,000 characters of the owner-scoped page text or note body, with its title and description, only after current v4 library-AI consent and an explicit UI action. The summary is validated, stored separately from media analysis with generation/model/prompt/source-hash/token/cost provenance, and linked back to its saved item. It shares the monthly AI reservation ledger and has a five-request/15-minute limit. The source hash covers bounded title, description, and content; reads detect stale summaries after source changes and offer regeneration. No raw source text is copied into the summary table. The summary migration remains local; only a mocked provider was used.
- Grounded Q&A now uses disclosure v5, covering bounded Q&A text/media-analysis excerpts/history, matching typed entity labels, and explicitly requested saved-item source text. Consent v1-v4 no longer authorizes provider calls. Matching OCR/transcript/media summaries and typed labels are included only from the retrieved items owned by the signed-in user.
- `npm.cmd run check` passed: API/web typecheck and lint, 89 API tests, and production builds. The web build retains the existing large-chunk warning. `git diff --check` passed. Browser interaction and hosted migration/runtime evidence remain open.
