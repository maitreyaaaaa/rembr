# IScraper findings and Rembr improvement register

## How to read this register

Findings must identify whether they are (a) confirmed in current source, (b) historical intent, (c) externally unverified, or (d) a proposed Rembr change. Severity indicates potential impact, not exploitability proof. Findings from delegated reviews are provisional until the primary audit reconciles their source locations and evidence. No finding in this document authorizes changes to the reference repo.

## Remediation priority

Use the [roadmap severity definitions](../rebuild-plan/phase-gated-roadmap.md#how-to-run-the-phases) when assigning Critical/High/Medium/Low. Critical/High block a phase gate; Medium/Low still require a named owner and explicit acceptance before closure.

1. Tenant isolation, URL fetch safety, credential/revocation controls, and deletion consistency.
2. Durable job correctness, idempotency, leases, retry classification, and source artifact provenance.
3. End-to-end capture-to-search reliability, extension integration, accessibility, and failure UX.
4. Search quality, optional enrichment, visual distinction, analytics, and secondary workflows.

## Primary-audit reconciliation checklist

- [ ] Open each extension finding in the source and verify line references; distinguish actual behavior from missing test coverage.
- [ ] Trace security boundary scripts, Supabase policies, route handlers, worker queries, and migrations.
- [ ] Add evidence for all delete/export and provider-retention behavior.
- [ ] Reconcile Notion historical ADRs with current implementation and mark superseded decisions.
- [ ] Record Codex Security / REA scan results only if their full workflow reaches a trustworthy terminal result; otherwise label them unavailable or partial.
- [ ] Replace provisional labels when source evidence is verified or refuted.
