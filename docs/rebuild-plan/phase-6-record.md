## Acceptance evidence

### Account-freeze groundwork

- 2026-10-30 follow-up: the export sanitizer now omits `account_deletion_steps.progress_cursor`, which can contain private storage-key traversal state. A regression test plants a sentinel cursor and confirms it is absent from the personal export.
- The account data map and Settings panel explicitly disclose that deletion step checkpoints, deletion audit events, owner work leases, and the media cleanup queue are operational records excluded from counted categories. Completed or cancelled deletion workflow records and terminal export-history rows are purged after 90 days; unresolved deletion requests remain available for recovery.
- Admins can view aggregate operational counts, search accounts by bounded email prefix, and open a minimal detail view with data-category counts, safe security-event labels, and latest deletion status. Read routes are no-store and use a separate audit table with hashed target IDs, query presence/length, and bounded pagination metadata; raw search text is never written. Administrator-access audit rows expire after 90 days.

- Shared active-owner locks fence account, library, import, AI, knowledge, and export writes against a concurrent account freeze. Provider work uses expiring owner leases with heartbeats; capture media and export artifacts persist planned storage keys before writing so deletion and recovery can find orphaned objects.
- The source-backed account activity ledger is now wired locally for export and import transitions, background processing failures/blocks/retries, search failures, analysis use, and safe deletion progress. It stores only an allowlisted event name and timestamp; owner activity is bounded and session-scoped, and the table is included through the shared data map in export and deletion with 90-day cleanup. The admin timeline omits ledger entries already represented by import/export status rows to avoid duplicate transitions. The global admin audit feed also includes the bounded, redacted activity events.
- Account data map, personal-data export, request/cancel/approve/retry deletion, security activity, and audited admin views are implemented locally on this branch. Admins can see aggregate operational counts, bounded account lookup/detail, worker queue totals/oldest waiting timestamps, up to 50 recent redacted import summaries, a redacted global audit stream, and a bounded per-user timeline over known security, activity, deletion, export, import, and admin-access records. Authenticated users denied admin/support access create redacted audit events identifying only a fixed action label and required/actual role.
- Admins can now grant, change, and revoke support/admin roles through a confirmed, rate-limited route; the transaction rechecks the actor, prevents self-change and last-active-admin demotion, and records only a hashed target plus role transition. Focused route/concurrency tests pass. The Phase 6 gate remains open: hosted Supabase migration/storage behavior, authenticated browser and accessibility review, full data-field coverage, environment-specific verification of first-admin bootstrap, external retention evidence, the complete source activity-event inventory, and approved billing remain open.
