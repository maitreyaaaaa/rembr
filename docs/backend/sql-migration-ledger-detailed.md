## Cross-migration schema domains

| Domain | Main tables / sequence |
|---|---|
| Identity & tenant data | `users`, profile, onboarding, admin state; user-auth cascade is the root. |
| Imports & library | `imports`, `saved_items`, collections, assets/notes, analysis, archives, link checks/reminders, Smart Collections. Same-user composite FKs were added incrementally. |
| Indexing/search | Text/visual embeddings, processing jobs, retry/lease RPCs, semantic match RPC, search events/feedback, shared budget RPC. |
| Billing | Provider credential schema, accounts, usage/transactions, package/purchase and admin adjustment ledgers; atomic paid debit and purchase-completion functions. |
| Access/integrations | Hashed extension tokens, Lens events, Telegram capture connections. |
| Privacy/audit | Data export request/step/storage, deletion request/step/hash audit, activity/security audit/correlation. |
| Automations | Automations/runs/chats/messages; late migrations deliberately make them API-only. |

## Ordering and dependencies

1. Base tables and RLS precede provider/billing, profiles, token/upload, and library extensions.
2. Vector extension moves into `extensions` before semantic search references `extensions.vector`.
3. Job lease implementation is successively replaced: `202605110001` → `202605240003` (token/retry/max attempts) → `20260926173449` (per-user advisory lock) → `20260926173500` (revoke all historical overloads).
4. Deletion statuses and tenant-scoped step ownership are changed in later migrations; use the final status set rather than reading the initial check alone.
5. Automation tables first remove client grants/policies, then a final migration repeats the API-only revocation for existing installations.
6. Storage bucket settings are reasserted across migrations. Compare final bucket size/MIME settings with runtime configuration and every route’s validator.

## Findings and unresolved verification

### Repository-evidenced findings

- `complete_credit_purchase` is a `SECURITY DEFINER` RPC with no explicit grant revocation in the migration file. Its effective ACL is a high-priority hosted audit item before credit checkout is enabled; no claim is made here about live exposure.
- `202605290001_saved_item_source_dates.sql` uses a regex predicate then casts source text. Invalid date values with a matching prefix may throw during migration; use safe parsing/validate production rows first.
- `202605270001_phase6j_supabase_performance_indexes.sql` explicitly says not to apply to production without explicit approval (`:1-3`). Preserve this distinction in deployment records.
- `user_provider_credentials` and `user_ai_keys` schema/RLS exist, and provider helper/catalog code exists, but migration evidence alone does not prove production CRUD or secret lifecycle. The application source audit found no orchestration CRUD call sites.
- `capture_connections.token_hash` references a globally unique token hash but not `(user_id, token_hash)`. A row for one user could structurally reference another user's token if an application path inserts that combination; API ownership logic should be verified or schema should enforce same-user linkage.
- Multiple RLS policies are broad `FOR ALL` user-owned rows by design. The backend uses a service-role store, which bypasses RLS; tenant predicates and API authorization must be audited separately.

### Hosted/environment facts not available from SQL files

- Which migration versions were applied, any manual SQL, and current schema drift.
- Effective privileges for `PUBLIC`, `anon`, `authenticated`, `service_role`, and any custom role on all relations/functions, including legacy RPC overloads.
- Supabase storage policies/bucket state, object paths, and whether service-role bypass is configured as expected.
- Whether the deployment's `public` schema grants object creation to untrusted roles, relevant to `SECURITY DEFINER SET search_path=public` functions.
- Data validity for casts/backfills and whether index builds are safe for table size/locks.

## Rebuild guidance for Rembr

Create a clean ordered migration set and a schema contract test covering tables, checks, composite tenant FKs, indexes, buckets, policies, and function ACLs. Keep SQL state machines atomic for billing and worker claims; explicitly revoke `PUBLIC` from every `SECURITY DEFINER` function before granting least privilege; pin safe search paths; avoid data migration casts that can fail on malformed historical values; and test migrations against realistic prior-version snapshots as well as a blank database. Add an environment migration-version gate and an ACL audit query before enabling paid flows or service-role API-only tables.
